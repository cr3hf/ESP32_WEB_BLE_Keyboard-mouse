## 项目简介

本设备将 ESP32-S3 实现为一个**免驱的蓝牙 HID 复合设备**：电脑在蓝牙设置中配对一次后，自动识别为「鼠标 + 键盘」，无需安装任何驱动。

核心能力是**随机动作模拟**：配对并按下 `KEY2` 启动后，动作引擎按预设概率随机抽取并执行一组拟人化的鼠标 / 键盘动作（拖拽、点击、滚轮、方向键、休息），循环不停；按下 `KEY0` 立即停止并释放所有按键。

此外，设备内置 **SoftAP 热点 + Web 控制台**，可通过浏览器实时调整运行模式、动作权重、动作序列、定时任务与 WiFi 配网，所有配置断电不丢失（存于 NVS）。

## 硬件要求

本固件支持 **两种硬件形态**，二者功能完全一致，差异仅在物理按键的有无：

| 形态 | 说明 |
| --- | --- |
| **A. 带 XL9555 扩展按键板** | 板载 XL9555 I2C IO 扩展芯片，提供 4 个物理按键（KEY0~KEY3）作为控制面 |
| **B. 无 XL9555 精简板** | 不焊接 XL9555，硬件按键被自动禁用。但仍可通过 **板载 BOOT 键（GPIO0）**、**Web 配置控制台**、**定时任务** 完整控制设备，不影响其余任何功能 |

两种形态共用的部分：

| 项目 | 说明 |
| --- | --- |
| 主控 | ESP32-S3（Xtensa，建议 WROOM-1-N4R2：4MB Flash + 2MB PSRAM 及以上） |
| 蓝牙 | 仅支持 BLE（ESP32-S3 不支持经典蓝牙 BR/EDR） |
| 状态 LED | GPIO1 普通推挽输出（低电平亮 / 高电平灭），可通过 `LED_STATUS_GPIO` 配置 |
| 开发框架 | ESP-IDF v5.3.5 |

> 上电时固件会自动探测 XL9555 是否可用：不可用则打印 `XL9555 不可用，硬件按键已禁用`，仅保留 BOOT 键 + Web + 定时三种控制方式。

## 功能特性

- **BLE HID 复合设备**：复合报告描述符，单 Report Map 内含鼠标（Report ID 1）与键盘（Report ID 2）两个集合。
- **Just Works 免密配对**：配对信息持久保存于 NVS，断电后自动重连。
- **随机动作引擎**：加权随机调度 8 类动作（拖拽 / 点击 / 滚轮 / 方向键 / 休息 / 滑动 / 打字 / 切换程序），循环执行，可被随时中断。
- **安全停止**：任何延迟 / 循环均可被 `KEY0` 或蓝牙断开中断，退出前强制释放鼠标按键与键盘按键，无残留。
- **复位落点校准**：采用「经验值两步法」将光标推回屏幕中心（不依赖屏幕几何，规避系统指针加速）。
- **按键控制面**：启停 + 组合键重置蓝牙配对。
- **WiFi Web 控制台**：SoftAP 常开 + 并发 STA，浏览器可视化配置模式 / 序列 / 定时任务 / 配网。
- **定时任务**：定时启停、定时单动作、周期循环三类规则。
- **并发安全**：统一发送队列 + 单一发送任务模型，避免 HID 协议栈竞态。

## 按键控制面

设备支持两类物理按键，可单独或同时使用；即使完全没有物理按键，也不影响核心功能（见下方的「无按键」说明）。

### 形态 A：XL9555 扩展按键（KEY0~KEY3）

4 个按键挂在 XL9555 的 P4~P7，读回字节位（低电平 = 按下）：

| 按键 | XL9555 引脚 | 功能 |
| --- | --- | --- |
| KEY2 | P1_5 (bit1) | **启动**：下降沿触发，仅在停止态下生效 |
| KEY0 | P1_7 (bit3) | **停止**：下降沿触发，立即停止动作并释放全部按键 |
| KEY3 | P1_4 (bit0) | 短按 → **停止动作并复位鼠标**（确认落点，停止态下同样执行） |
| KEY1 | P1_6 (bit2) | 短按 → 运行额度 **+10 分钟**（LED 闪一下确认）；与 KEY3 长按 3 秒 → 重置蓝牙；松开后 5s 内再次长按 → 恢复出厂（账号+参数） |

**组合键（KEY1 + KEY3 同时长按 3 秒）**：停止动作 → 断开主机 → 删除配对 → 轮换随机蓝牙地址 → 重新广播（仅清蓝牙）。若**松开后 5 秒内再次长按 3 秒**，则额外恢复出厂设置（Web 账号重置为 admin/admin，全部参数恢复默认并落盘）。用于清除旧配对、更换电脑重连，或以两段式防误触地恢复出厂。组合键生效期间屏蔽 KEY3 单按复位与 KEY0/KEY2 边沿判定，防止误触发。

### 形态 B：板载 BOOT 键（GPIO0，始终可用）

无论是否焊接 XL9555，ESP32-S3 的 **板载 BOOT 键（GPIO0）** 都作为兜底控制键：

| 操作 | 功能 |
| --- | --- |
| **短按** | 切换动作启停（运行 ↔ 停止，单键切换） |
| **长按 ≥ 3 秒** | 重置蓝牙；松开后 5s 内再次长按 → 恢复出厂（账号+参数），效果等同 KEY1+KEY3 组合键 |

BOOT 键独立于 XL9555，即使硬件按键全部禁用也能正常工作。

### 无按键也能用

若设备既无 XL9555 也无 BOOT 键场景（如纯远程部署），以下控制方式**完全等效**，且断电保持：

- **Web 配置控制台**：页面内「启动 / 停止」按钮（`/api/control`）。
- **定时任务**：配置定时启停 / 周期循环规则，到点自动启停。
- **蓝牙重置 / 恢复出厂**：在 Web 控制台点「恢复出厂设置」；或长按 BOOT 键 / KEY1+KEY3 组合键 3 秒（仅清蓝牙），**松开后 5 秒内再次长按**则额外恢复出厂（账号+参数）。

> 结论：物理按键是「便捷控制面」，不是功能依赖项。任意一种硬件形态下，核心动作模拟、配对、配置、定时能力均完整可用。

## 快速开始

1. 安装 [ESP-IDF v5.3.5](https://docs.espressif.com/projects/esp-idf/zh_CN/v5.3.5/esp32s3/) 并配置环境（`idf.py` 可用）。
2. 克隆仓库并进入目录：
   ```bash
   git clone https://github.com/cr3hf/ESP32_WEB_BLE_Keyboard-mouse.git
   cd ESP32-BLE-KM
   ```
3. 编译并烧录（替换 `/dev/ttyUSB0` 为你的串口号）：
   ```bash
   idf.py set-target esp32s3
   idf.py build
   idf.py -p /dev/ttyUSB0 flash monitor
   ```
4. 电脑蓝牙配对（见下），按 `KEY2` 启动。

## 蓝牙配对（Windows）

1. 给 ESP32-S3 上电，串口出现「等待新设备配对」提示。
2. 打开 Windows **设置 → 蓝牙和其他设备 → 添加蓝牙或其他设备 → 蓝牙**。
3. 选择设备广播名（默认 `BLE_KM`，便于在配对列表识别），系统自动完成 Just Works 配对。
4. 配对成功后，Windows 蓝牙设备列表中显示为**一个复合设备**（如 `BLE_KM`），其内部同时包含键盘与鼠标两个 HID 接口，并非拆分为两个独立设备。按 **KEY2** 启动随机动作，按 **KEY0** 停止，状态 LED 在执行时点亮。
5. 如需仅重新配对其他电脑：在 ESP32 上 **KEY1 + KEY3 同时长按 3 秒** 触发蓝牙重置，再于新电脑上重新添加设备。若需**恢复出厂**（账号 admin/admin + 全部参数默认），则在本长按松开后 **5 秒内再次长按 3 秒**。

> 重置后 Windows 蓝牙列表可能出现两个同名设备（旧失效记录 + 新地址），旧的可「删除 / 忘记此设备」清理，不删也不会重连风暴。

## Web 配置控制台

设备启动后**始终开启 SoftAP 热点**：

| 项目 | 值 |
| --- | --- |
| SSID | `BLE_KM_XXXX`（XXXX 为设备 MAC 地址后四位，例如 `BLE_KM_A1B2`） |
| 密码 | `12345678` |
| AP IP | `192.168.4.1` |

AP 永不关闭，无论 STA 是否连上路由器，均可通过 `192.168.4.1` 访问页面；STA 连上路由器后其局域网 IP 同样可访问（HTTP Server 监听 `0.0.0.0`）。

### 控制台功能

- **状态栏**：AP IP、STA IP、蓝牙连接状态、引擎运行状态、启动/停止按钮（每 3 秒轮询 `/api/status`）。
- **登录鉴权**：页面需登录后访问，默认用户名 / 密码为 `admin` / `admin`。登录后点工具栏「修改密码」可随时修改用户名与密码并持久化（存于 NVS，断电不丢失），下次登录使用新凭据；如需将账号与全部参数一键恢复出厂，登录后点工具栏「恢复出厂设置」即可（账号重置为 `admin`/`admin` 且全部参数恢复默认，立即生效无需再保存）。
- **运行模式**：随机模式（五类权重数字输入）/ 序列模式（选项卡切换）。
- **动作序列编排**：从五类动作添加 / 上移 / 下移 / 删除；循环策略可选「顺序循环」或「乱序洗牌」。
- **定时任务**：三类规则（可多条）——定时启停、定时单动作、周期循环。
- **WiFi 配网**：填写路由器 SSID / 密码并「保存并连接」，设备并发联网，AP 不关闭。
- **多套参数（参数套）**：内置 3 套互相独立的参数（动作时间 / 运动模式 / 随机权重）。顶部下拉框用于切换「当前编辑套」——切换仅替换页面显示的套，**不会自动保存**；点「保存配置」会把全部三套写回设备，并以当前选中套作为生效套。
- **动作时间 + 运动模式**：运动模式（鼠标复位 / 活动范围等运动参数）已并入「动作时间配置」卡片，采用与动作时间完全一致的卡片框样式，每套参数独立。
- **导入 / 导出**：导出把页面当前全部参数（含三套）序列化为 JSON 下载；导入把 JSON 深合并进当前配置并重渲染页面。二者都只操作内存，**只有点「保存配置」才会写入设备 FLASH**。

### REST 接口

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/` | GET | 内置控制台页面 |
| `/api/status` | GET | `{ap_ip, sta_ip, bt, running}` |
| `/api/config` | GET | 当前配置 JSON |
| `/api/config` | POST | 保存配置并实时应用到引擎（含全部三套参数 + 生效套标记） |
| `/api/control` | POST | `{"action":"start"\|"stop"}` 启停引擎 |
| `/api/wifi` | POST | `{"ssid","pass"}` 保存并连路由器 |
| `/api/login` | POST | 校验用户名/密码，成功返回 Bearer token |
| `/api/logout` | POST | 清除当前会话 token |
| `/api/setauth` | POST | 修改登录用户名/密码（需登录，写入 NVS 持久化） |
| `/api/factory_reset` | POST | 恢复出厂设置（需登录）：登录账号重置为 `admin`/`admin`，并重置全部参数到默认值，立即写入 NVS |

## 随机动作引擎

默认处于停止态，按 `KEY2` 后开始，按概率随机抽取动作，循环执行。每个动作自带随机延迟之外，**额外追加 100ms 保护延迟**才进入下一个动作。

### 动作列表与默认权重

| ID | 动作 | 权重 | 内容 |
| --- | --- | --- | --- |
| 0 | 模拟鼠标拖拽 | 0 | 按住左键 → 活动范围内分片步进拖过去，重复 1~5 次，间隔 600~1500ms → 松开 → 鼠标复位 → 延迟 500~5000ms |
| 1 | 模拟鼠标点击 | 50 | 随机目标点步进移过去 → 单击左键（按下 20~250ms），重复 1~10 次，间隔 100~1000ms → 鼠标复位 → 延迟 1000~5000ms |
| 2 | 模拟鼠标滚轮 | 50 | 随机目标点 → 随机上下滚轮（步进 1~8），重复 1~5 次，间隔 100~500ms → 滚轮归位（累计和归零）→ 鼠标复位 → 延迟 1000~5000ms |
| 3 | 模拟键盘方向键 | 30 | 随机敲击上/下/左/右，重复 1~20 次，间隔 50~800ms → 延迟 1000~5000ms |
| 4 | 模拟休息 | 35 | 随机延迟 1~20 秒 |
| 5 | 模拟滑动鼠标 | 50 | 随机方向滑动随机距离（分片步进），重复 1~20 次，间隔 100~500ms → 鼠标复位 → 延迟 500~1000ms |
| 6 | 打字（随机单词） | 0 | 从单词表随机抽词逐字符发送，每词后加空格；词数 1~5，字符间 40~700ms，词尾空格 40~1000ms |
| 7 | **切换程序（Alt+Tab）** | 0 | 按住 Alt 点 Tab 切换窗口，切换次数默认 **0~1 次**（页面可放宽至 0~999），每次按键间隔默认 **500~1000ms**（可放宽至 50~5000ms），动作后休息默认 **700~1500ms**（可放宽至 50~60000ms） |

> - 概率权重代码用 `esp_random() % total` 取模，合计不必严格为 100，仅相对比例决定分布；权重 0 表示该动作不参与随机抽取（拖拽、打字、切换程序默认禁用）。
> - 「切换程序」的三组参数（切换次数 / 按键间隔 / 动作后休息）与其他动作一样在 **Web 控制台 → 动作参数** 卡片中实时可调，并随配置导入导出。
> - 切换次数取 0 时本次不发送任何按键（等价于空转一次后直接进入休息）。

### 关键机制

- **鼠标活动范围限制**：逻辑光标坐标以屏幕中心为原点，全程钳制在矩形范围内（默认 ±500 / ±200 像素），并按系统显示缩放自动折算（`基准 × 100 / SCALE_PCT`）。
- **鼠标复位**：BLE 鼠标是相对位移协议，读不到绝对位置；Windows 指针加速导致几何回中不可靠，故采用「撞角 → 回中心」经验值两步法，落点需按实测微调（`MOUSE_HOME_*` 宏）。
- **可中断延迟**：所有延迟基于 `xEventGroupWaitBits`，停止 / 断连事件到来时最多在「一次分片延迟（约 8~10ms）」内被唤醒。
- **强制释放**：每个动作唯一出口与引擎主循环 STOP 分支均调用 `action_release_all()`，发送键盘全 0 报文一次性释放包括 Alt/Shift/Ctrl 在内的所有按键，杜绝按键卡死残留。
- **大位移分片**：>127 计数的位移按 ≤120 切片发送，阻塞投递保证轨迹完整。
- **整数数学**：方向换算用 Q15 定点正弦表（64 点），不引入浮点 `sinf/cosf`，规避 libm。

## 编译与烧录

```bash
# 设置目标芯片
idf.py set-target esp32s3

# 配置（可选，默认 sdkconfig.defaults.esp32s3 已就绪）
idf.py menuconfig

# 编译
idf.py build

# 烧录并监视（替换串口号）
idf.py -p /dev/ttyUSB0 flash monitor
```

> **注意**：修改 `sdkconfig.defaults.esp32s3` 后，若工程根目录已存在旧 `sdkconfig`，需删除 `sdkconfig` 或执行 `idf.py fullclean` 再构建，否则分区配置不会生效。
>
> 修改 `action_engine.h` 中的宏参数后，必须**重新编译（建议 fullclean 后 build）并烧录**，宏值在编译期固化进固件，运行时无法更改。

> 如需自定义 AP 名称 / 密码 / 登录账号 / STA 默认凭据 / 页面品牌等，可新增 `main/local_defs.h`（用法见 `main/defaults.h` 顶部说明）覆盖默认值；该文件已被 `.gitignore` 忽略，不会进入公开仓库。

## 可调参数（action_engine.h）

所有随机区间、概率权重、屏幕缩放、复位经验值均集中在 `main/action_engine.h` 以宏定义，修改只需改这一个文件。每个宏用 `#ifndef … #endif` 包裹，也可在 `sdkconfig` / `CMakeLists.txt` 的 `add_definitions()` / 编译 `-D` 中覆盖。

| 类别 | 宏 | 含义 | 默认 |
| --- | --- | --- | --- |
| 概率权重 | `ACT_W_DRAG / CLICK / WHEEL / ARROW / REST / MOVE / WORD / ALT_TAB` | 八类动作抽取权重 | 0 / 50 / 50 / 30 / 35 / 50 / 0 / 0 |
| 活动范围 | `MOUSE_POS_LIMIT_X / Y` | 相对屏幕中心的半范围基准（像素） | 500 / 200 |
| 显示缩放 | `SCREEN_SCALE_PCT` | 系统显示缩放百分比（自动缩小有效范围） | 125 |
| 复位撞角 | `MOUSE_HOME_CORNER` | 复位撞哪个角 | `CORNER_TOP_RIGHT` |
| 复位经验值 | `MOUSE_HOME_PUSH_PX / BACK_X / BACK_Y` | 撞角 / 回中心位移计数（需实测调校） | 1500 / 600 / 200 |
| 动作参数 | `DRAG_* / CLICK_* / WHEEL_* / ARROW_* / REST_* / MOVE_* / WORD_*` | 各自重复次数、间隔、步进等随机区间 | 见源码 |
| 切换程序 | `ALT_TAB_REPEAT_MIN / MAX` | 单次动作的切换次数（0=本次不切换），页面可放宽至 0~999 | 0 / 999 |
| 切换程序 | `ALT_TAB_INTERVAL_MIN / MAX` | 每次按键之间的间隔（ms），页面可放宽至 50~5000 | 50 / 5000 |
| 切换程序 | `ALT_TAB_END_DELAY_MIN / MAX` | 动作结束后的休息时间（ms），页面可放宽至 50~60000 | 700 / 60000 |
| 切换程序 | `ALT_TAB_HOLD_MS` | Tab 按下保持时长（ms） | 10 |
| 时序 | `ACTION_GUARD_DELAY_MS` | 动作间保护延迟 | 100 |
| 时序 | `ACTION_MOVE_STEP_MS` | 分片移动帧间延迟 | 8 |

**常见调参场景**：

- 调整节奏 / 概率：改 `ACT_W_*` 与对应 `REPEAT` / `INTERVAL`；整体更慢就调大各 `INTERVAL_MIN` 与 `ACTION_MOVE_STEP_MS`。
- 适配缩放屏：把 `SCREEN_SCALE_PCT` 设为系统实际缩放值（如 125、150）。
- 复位落点偏角（回多了）：调小 `MOUSE_HOME_BACK_X/Y`；偏反方向（回少了）：调大；撞角未到边界：调大 `MOUSE_HOME_PUSH_PX`。
- 复位撞错角：按屏幕方位设 `MOUSE_HOME_CORNER`（右上 / 左上 / 右下 / 左下）。

## 常见问题

**Q：电脑配对后识别不到鼠标 / 键盘？**
A：确认设备广播名正确、配对为 Just Works 免密；Windows 蓝牙列表里它表现为**一个复合设备**（同时含键鼠两个接口），并非两个独立设备，需要在那一个设备的属性 / 设备管理器「人机接口设备」下查看键盘与鼠标接口是否都就位。

**Q：停止后鼠标左键卡住？**
A：正常停止会调用 `action_release_all()` 强制释放。若仍卡住，按 `KEY0` 再按 `KEY3`（停止并复位）兜底释放；蓝牙未连接时仅停动作。

**Q：滚轮滚动后光标偏移？**
A：动作 3 结束时按累计和精确归位（发 `-wheel_sum`），确保总和为 0；若偏差来自大位移分片，属正常轨迹。

**Q：复位后光标不在中心？**
A：按 `KEY3` 触发「停止并复位」确认落点，调 `MOUSE_HOME_BACK_X/Y` 与 `MOUSE_HOME_PUSH_PX` 经验值收敛（改完 fullclean 重编）。

**Q：如何切换电脑重连？**
A：ESP32 上 `KEY1 + KEY3` 长按 3 秒仅重置蓝牙（换地址 + 清配对），再于新电脑添加设备。若需**恢复出厂**（账号/参数恢复默认），在松开后 **5 秒内再次长按 3 秒** 即可。

**Q：Web 页面打不开？**
A：确认连接 AP `BLE_KM_XXXX`（XXXX 为 MAC 后四位，密码 `12345678`）或设备已连路由器，浏览器访问 `192.168.4.1`。
